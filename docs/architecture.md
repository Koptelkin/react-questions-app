# Архитектура react-questions-app

> Актуальная версия. История изменений есть в git (`git log -p docs/architecture.md`).

## Стек

- React + Vite, чистый JavaScript (без TypeScript)
- Состояние: только хуки React (`useState`, `useEffect`, кастомные хуки), без Redux
- Стили: CSS Modules
- `dompurify`: очистка HTML из API перед вставкой в DOM

## Страница

На одной странице два независимых блока:

- **Вопросы**: список карточек-аккордеонов с пагинацией, данные приходят из API;
- **Фильтры**: поиск и группы фильтров. Изменение фильтров запускает новый запрос к API.

Блоки связаны общим состоянием запроса, которое хранится в `QuestionsPage` (lifting state up):

```
filters: {
  search: string,
  specialization: id | null,  // одиночный выбор (API принимает один specializationId)
  skills: id[],               // мультивыбор
  complexity: string[],       // мультивыбор диапазонов, как на чипах: ['1-3', '9-10']
  rating: number[],           // мультивыбор: [4, 5]
}
page: number
```

Группы фильтров комбинируются: можно одновременно выбрать специализацию, навыки, сложность и рейтинг. Специализация — одиночный выбор, остальные группы — мультивыбор.

Фильтрацию выполняет бэкенд. Фронтенд только отправляет выбранные id и значения и показывает то, что вернул сервер. Сам он вопросы не фильтрует.

### Параметры API вопросов (`/questions/public-questions`)

| Поле `filters` | Параметр API | Формат |
|---|---|---|
| `search` | `title` | строка |
| `specialization` | `specializationId` | одно число |
| `skills` | `skills` | через запятую: `skills=1,2,3` |
| `complexity` | `complexity` | отдельные числа через запятую: `['1-3', '9-10']` → `complexity=1,2,3,9,10` |
| `rating` | `rate` | через запятую: `rate=4,5` |

Массивы передаются строкой через запятую (`join(',')`), `URLSearchParams` сам кодирует запятую в `%2C`. Сложность в состоянии хранится диапазонами, как выбрал пользователь (чипы `1–3`, `4–6`, `7–8`, `9–10`), а в числа для API разворачивается в `fetchQuestions` чистой функцией (`'1-3'` → `[1, 2, 3]`). Опция сложности: `{ value: '1-3', label: '1–3' }` — дефис в значении, тире в подписи. Пустые значения в запрос не попадают. Параметр `skillFilterMode` не отправляется: документации к нему нет, используется поведение сервера по умолчанию — **«И»**: вопрос должен содержать все выбранные навыки (проверено: `skills=6` → 88, `skills=22` → 24, `skills=6,22` → 1).

Справочники (`/specializations`, `/skills`):
- нужные поля: `id` → `value`, `title` → `label`, `imageSrc` → `icon` (у навыков URL картинки **или `null`**: иконки есть примерно у трети нормальных навыков; у специализаций поле не берётся);
- ответ с пагинацией (специализаций ~45, навыков ~74), поэтому все записи забираются одним запросом с `limit=100` (проверено: сервер его принимает);
- в справочниках есть тестовые записи других разработчиков. Нужные записи отбираются в адаптере (`fetchSpecializations` / `fetchSkills`) по `createdBy === null`. Это эвристика: если нужная запись когда-нибудь получит автора, она пропадёт из фильтров;
- для специализаций дополнительно требуется `imageSrc === null`: у оригинальных специализаций картинок нет, а иконки добавляли только к тестовым записям (например, «NEWWWWW» без автора, но с картинкой). Тоже эвристика: если оригинальной специализации добавят иконку, она пропадёт. Для навыков это условие **не подходит**: у нормальных навыков картинки есть;
- у навыка есть массив `specializations` (к каким специализациям он относится). Пока не используется.

## Дерево компонентов

```
QuestionsPage                  ← хранит параметры запроса (useState), связывает блоки
├── QuestionsSection           ← карточка с заголовком
│   ├── QuestionList           ← загрузка / ошибка / пусто / список
│   │   └── QuestionItem ×N    ← аккордеон
│   │       ├── (шапка) заголовок + шеврон
│   │       └── (тело)
│   │           ├── (строка меты)    ← div-обёртка, flex: мета слева, меню справа
│   │           │   ├── QuestionMeta ← рейтинг, сложность (<dl>)
│   │           │   └── QuestionMenu ← ⋮ меню доп. действий (ОТЛОЖЕНО, не в текущей итерации)
│   │           └── answer (HTML)
│   └── Pagination
│
└── FiltersPanel
    ├── SearchInput
    ├── RemoteFiltersGroups     ← вызывает useFilterOptions; загрузка / ошибка / две группы
    │   ├── FilterGroup        (специализация, одиночный выбор)
    │   └── FilterGroup        (навыки, мультивыбор)
    └── FilterGroup ×2         ← сложность и рейтинг (опции из констант)
        ├── Chip ×N            (каждая FilterGroup)
        └── «Посмотреть все»
```

`RemoteFiltersGroups` получает только `filters` и `onFiltersChange`. Справочники нужны только ему, поэтому хук вызывается внутри (состояние рядом с тем, кто его использует). Загрузка и ошибка у обеих групп общие (`Promise.all`: всё или ничего), поэтому проверяются один раз ранними возвратами: при загрузке выводится текст «Загрузка данных», при ошибке — текст ошибки вместо обеих групп.

`FilterGroup` универсальный, пропсы примерно такие: `title, options, selected, onChange, multiple, collapsedCount`. У опции может быть необязательное поле `icon` (используется в навыках).

Источники опций для групп:

| Группа | Откуда опции |
|---|---|
| Специализация | API, отрисовываются динамически |
| Навыки | API, отрисовываются динамически (с иконками) |
| Уровень сложности | константы во фронтенде (если API их не отдаёт) |
| Рейтинг | константы во фронтенде (если API их не отдаёт) |

## HTML-семантика

| Блок | Разметка |
|---|---|
| Страница | `<main>`: `<section aria-labelledby>` для вопросов + `<aside>` для фильтров |
| Список вопросов | `<ul>` / `<li>` |
| Аккордеон | `<h3><button aria-expanded aria-controls="{id}">…</button></h3>` — шапка (кнопка, а не `<div onClick>`); тело — `<div id="{id}" hidden={!isOpen}>` без `role="region"` (панелей много, ориентиры засорят навигацию). Тело рендерится всегда и прячется атрибутом `hidden`: `aria-controls` всегда ссылается на существующий элемент, и позже можно добавить анимацию. Элементу с `hidden` не задавать `display` в CSS, иначе он перебьёт скрытие. Уникальный id через `useId` |
| Мета | один `<dl>` (список описаний, не таблица) с двумя парами, каждая в `<div>` для стилизации плашки: `<div><dt>Рейтинг:</dt><dd>4</dd></div>` и `<div><dt>Сложность:</dt><dd>10</dd></div>` |
| Пагинация | `<nav aria-label="Пагинация">` + `<ul>` кнопок, текущая страница с `aria-current="page"`, многоточие `aria-hidden` |
| Фильтры | `<form role="search">`, поиск `<input type="search">` с `<label>`, каждая группа `<fieldset>` + `<legend>` |
| Чипы | `<button aria-pressed>` (проще) или скрытые `checkbox` / `radio` + `<label>` (семантичнее). Специализация — одиночный выбор, остальные группы — мультивыбор |

## Состояние

| Состояние | Где | Как |
|---|---|---|
| Фильтры | `QuestionsPage` | `useState`, передаются пропсами в `FiltersPanel` |
| Страница | `QuestionsPage` | отдельный `useState`, при смене фильтра сбрасывается в 1 |
| Данные / загрузка / ошибка | `useQuestions(filters, page)` | `useState` + `useEffect` внутри хука |
| Открыт ли вопрос | `QuestionItem` | свой `useState(false)` в каждом вопросе: открыть можно несколько одновременно |
| Справочники фильтров / загрузка / ошибка | `useFilterOptions()` в `RemoteFiltersGroups` | `useState` + `useEffect`, один раз при монтировании; оба запроса параллельно через `Promise.all` |
| «Посмотреть все» | `FilterGroup` | `useState` |
| Текст поиска | `SearchInput` + `useDebounce` | наверх передаётся значение после задержки |

## Важные правила

1. Смена любого фильтра вызывает `setPage(1)`. Оба обновления делаются в одном обработчике `handleFiltersChange(key, value)` в `QuestionsPage` (не через `useEffect`): React объединяет их в один рендер и один запрос. Новый объект фильтров собирается функцией-обновлением `setFilters(prev => ({ ...prev, [key]: value }))`, чтобы обновления не затирали друг друга (например, поиск с задержкой и клик по чипу). `FilterGroup` отдаёт через `onChange` только новое значение группы, ключ фильтра добавляет `FiltersPanel`.
2. В `useQuestions` гонка запросов обрабатывается через `AbortController` в cleanup-функции `useEffect`.
3. Не передавать в зависимости `useEffect` объекты и массивы, которые создаются заново на каждом рендере.
4. Вычисление номеров страниц (`[1, 2, 3, '…', 24]`) вынесено в чистую функцию `getPageRange(current, totalPages)`, `Pagination` только рисует результат.
   - Размер страницы — константа `PAGE_SIZE` в `features/questions/constants.js`. Её использует только `fetchQuestions`: подставляет в `limit` и считает `totalPages = Math.ceil(total / limit)` по данным ответа. Адаптер возвращает `{ questions, totalPages }`.
   - `Pagination` (в `shared/ui`) не импортирует `PAGE_SIZE` и не знает про `total`: получает пропсами `currentPage`, `totalPages`, `onPageChange`. `onPageChange` вызывается с номером страницы (числом). Кнопки «Назад» / «Вперёд» блокируются (`disabled`) на первой / последней странице. При `totalPages === 0` (данные ещё не пришли) пагинация не рендерится.
5. Строка запроса собирается в одном месте, в `fetchQuestions`. Компоненты и хуки работают с массивами, о формате URL не знают. Базовый адрес сервера — константа `API_BASE_URL` из `shared/api/config.js`, путь ресурса (`/questions/public-questions`) — в самой функции запроса.
6. Ответы на вопросы (`longAnswer`, `shortAnswer`) приходят из API как HTML-строки. Они выводятся через `dangerouslySetInnerHTML` только после `DOMPurify.sanitize`. Очистка выполняется в адаптере `fetchQuestions` (один раз при получении), компоненты получают уже безопасную строку. Обёртка — `<div>`, не `<p>`: внутри свои `<p>`, `<ul>`, `<h2>`. Стили задаются вложенными селекторами от обёртки (`.answer p`), классы из API игнорируются.
7. Картинки вопросов (`imageSrc`) не выводятся, компонента `QuestionImage` нет.

## Отложено (следующие итерации)

- `getPageRange`: если между краем и окном пропущена ровно одна страница, показывать её номер вместо `'…'` (например, `[1, 2, 3, 4, 5, …]` вместо `[1, '…', 3, 4, 5, …]`). Сейчас многоточие ставится при любом пропуске.
- Кнопка «Повторить» при ошибке загрузки вопросов: повторный клик на ту же страницу не перезапускает запрос (`setPage` с тем же значением не вызывает рендер).
- `QuestionMenu`: иконка ⋮ в строке метаинформации (справа от рейтинга и сложности), по клику открывает дополнительные кнопки. Это сосед `QuestionMeta`, а не его часть: меню не метаданные и не должно лежать внутри `<dl>`. В текущей итерации не реализуется, компонент и иконку пока не создаём.

## Открытые вопросы

- [x] Рейтинг и сложность: **мультивыбор**. Рейтинг — `number[]`, сложность — `string[]` диапазонов, в API уходит развёрнутыми числами
- [x] Аккордеон: **можно открыть несколько вопросов** одновременно, состояние в каждом `QuestionItem`
- [x] Справочники специализаций и навыков: **приходят с API**, рендерятся динамически
- [x] Специализация: ~~мультивыбор~~ → **одиночный выбор**: API принимает один `specializationId`. Фильтрует бэкенд
- [x] Формат массивов в запросе: **через запятую** (`?skills=1,2`), см. «Параметры API вопросов»
- [x] Специализация: в Swagger `specializationId` — `number`, **только одно значение**
- [x] `skillFilterMode`: документации нет, **параметр не отправляем**. По умолчанию сервер применяет **«И»**: при нескольких навыках остаются вопросы, где есть все выбранные
- [x] Сложность в UI: по макету **диапазоны** `1–3`, `4–6`, `7–8`, `9–10`; в состоянии диапазоны, в API числа
- [x] Справочники: специализаций ~45, навыков ~74, забираются одним запросом; мусорные записи отсеиваются по `createdBy === null`
- [x] Справочники: сервер принимает `limit=100`, все записи приходят одним запросом
- [x] Навыки: критерий `createdBy === null` работает (проверено на 75 записях, остаётся 45). Пропускает одну мусорную запись «tmp». У большинства нормальных навыков `imageSrc === null`, так что иконка необязательна
- [x] Навыки: поле иконки — `imageSrc` (URL картинки)
- [x] Отображение загрузки и ошибки справочников: **один общий текст вместо обеих групп** в `RemoteFiltersGroups` (см. «Дерево компонентов»)
- [x] Снятие выбора: **в любой группе** повторный клик по выбранному чипу снимает выбор. Для специализации это `null` (вопросы всех специализаций)
